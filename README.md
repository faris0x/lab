# lab

`lab.faris0x.dev`: exact, step-by-step mathematics tools.

The live tools are **Simplex & Big-M** at `/optimisation`, the **Matrix
toolkit** at `/matrix`, **Complex numbers** at `/complex`, **Taylor &
Maclaurin series** at `/series`, **Truth tables** at `/logic`, **Graphs &
networks** at `/graphs`, the **Floating point toolkit** at `/floating-point`,
and **Boolean algebra** at `/boolean`. Tool routes stay at the top level: new
tools go at `/<topic>`, not nested under a second category.
The Argand axes use `d3-scale` for rounded ticks and consistent equal-aspect
scaling.

## Running it

Prerequisites:

- Node 24 (pinned in `.nvmrc`; `engines` rejects other majors).
- A Rust toolchain with `rustfmt`, `clippy`, and the `wasm32-unknown-unknown`
  target (`rustup toolchain install stable --component rustfmt clippy --target
  wasm32-unknown-unknown`).
- A matching `wasm-bindgen` CLI:
  `cargo install wasm-bindgen-cli --version 0.2.130 --locked` (or
  `npm run wasm:install`).

```sh
npm run dev                    # http://localhost:4321
npm run build                  # WASM + static site in dist/
npm run preview                # serve dist/
npm run check                  # astro check + svelte-check
npm test                       # Vitest unit tests
npm run test:e2e               # Playwright browser tests
npm run test:rust              # cargo tests for the exact solvers
npm run wasm                   # rebuild all eight WASM modules
```

The WASM build emits `public/wasm/<crate>/` (generated JS glue, `.d.ts` and
`.wasm`) and is gitignored. A fresh clone must build before previewing the
solvers.

On Termux, where `rustup` is not available and the packaged toolchain has no
matching `wasm32` std, build std from source:

```sh
WASM_BUILD_STD=1 npm run wasm
```

`scripts/env.sh` is an optional local override and is not needed on CI.

## What is built

- `rust/crates/mathcore`: exact `i64` rationals and the symbolic `a + bM`
  value, ordered with `M -> infinity`. No floating point, no big integers.
- `rust/crates/simplex`: model parsing, standard form, simplex + Big-M,
  tableau trace, LaTeX and prose generation. Compiles to a `cdylib` for
  `wasm32-unknown-unknown` and to an `rlib` for native tests.
- `rust/crates/linalg`: exact RREF, determinant, inverse, nullspace and
  linear systems, with a row-operation trace and LaTeX output.
- `rust/crates/complexnum`: exact complex arithmetic, polar form, de Moivre
  powers and nth roots in omega notation, with Argand points for the diagram.
- `rust/crates/graphnet`: graph algorithms on top of `petgraph`. Weights are
  exact rationals. Dijkstra, Floyd–Warshall, Kruskal and Prim return a trace
  and a complete LaTeX document.
- `rust/crates/series`: exact symbolic differentiation, rational coefficients,
  Taylor/Maclaurin expansion and heuristic general-term detection (for example
  `(-1)^n x^(2n+1)/(2n+1)!` for `sin x`).
- `rust/crates/logic`: propositional parsing, truth tables and verdicts.
- `rust/crates/floating`: exact base conversion, normalisation and custom or
  IEEE 754 encoding and decoding.
- `rust/crates/boolean`: truth tables, canonical SOP/POS, prime implicants and a
  minimal sum of products, built on the `logic` crate.
- `src/`: Astro static pages with one Svelte island per tool.
- `src/components/MathField.svelte`: WYSIWYG maths input built on MathLive.
  The custom keypad inserts LaTeX at the caret; every key label is rendered
  with KaTeX.
- `src/components/Keypad.svelte`, `Tabs.svelte`, `ExportBar.svelte`,
  `StepControls.svelte`, `StatusLine.svelte`: shared tool chrome.
- `src/components/LatexPreview.svelte`, `LatexText.svelte`: render the actual
  exported LaTeX document, not a separate hand-built preview. Copy, download,
  the preview and the source dropdown all use the same string.
- `src/lib/latex.ts`: shared LaTeX document builder and escaping.
- `src/lib/latex-preview.ts`: parses a generated document into headings,
  display maths, paragraphs and lists for the preview.
- `src/lib/math-input.ts`: converts MathLive's LaTeX to the canonical solver
  input, normalises Arabic-Indic/Persian digits, and evaluates simple exact
  numeric expressions (`1^5`, `2+3`, `\sqrt{4}`). Irrational roots are
  approximated to nine decimal places. The `expression` format preserves
  functions and variables for the series parser.
- `src/lib/series.ts`, `src/lib/logic.ts`, `src/lib/floating.ts` and
  `src/lib/boolean.ts`: typed async wrappers around their Rust WASM modules.
- `src/lib/tools.ts`: one registry for the nav and tool metadata.
- `src/lib/wasm.ts`: one loader for every `wasm-bindgen` module, with cached
  instances and trap recovery.
- `src/lib/lang.ts`, `src/lib/localize.ts`: the dormant English/Arabic layer.
  Arabic is frozen and the language selector is hidden.
- `public/wasm/{simplex,linalg,complexnum,graphnet,series,logic,floating,boolean}/`: generated by
  `scripts/build-wasm.sh` from the `wasm-bindgen` CLI output.
- `public/katex/` and `public/fonts/`: self-hosted. The dormant Arabic layer
  still loads Almarai from Google Fonts; no other third-party requests.

### Browser boundary

Each crate exports one `wasm-bindgen` function, `solve(&str) -> String`:
JSON in, JSON out. `src/lib/wasm.ts` loads the generated ES module, initialises
the WASM, and caches one instance per solver. A WebAssembly trap resets the
cache and retries on the next call instead of leaving the tool broken.
Tableaus and prose are rendered from the generated LaTeX with KaTeX, so the
on-screen notation and the `.tex` export use the same source.

Editable maths fields are `MathField` instances: MathLive renders the value
WYSIWYG, the shared keypad inserts LaTeX, and the canonical value sent to the
solver is derived from the field's LaTeX. Every displayed variable, number,
tableau, prose fragment and export is KaTeX/LaTeX. The UI face is Hubot Sans,
self-hosted as a variable WOFF2; monospace labels stay monospace as a
deliberate contrast.

The index page ships only the inline theme and dormant language scripts. Tool
pages hydrate the Svelte island, MathLive and KaTeX; WASM is fetched when a
solver is used.

### Trace -> UI, prose, LaTeX

The solvers emit a list of steps: tableaus, pivots, ratios and row operations
for simplex; matrices and row operations for linear algebra; distance and
spanning-tree decisions for graphs. The preview is parsed from the same
document that is copied or downloaded, so the screen and the `.tex` file
cannot drift.

## Conventions

- Non-negative decision variables only.
- Objective row written as `Z - c'x + M a = 0`; enter on the most negative
  coefficient, leave on the smallest non-negative ratio, tie-break by the
  lowest row.
- The tableau column `b.v.` lists the basic variable for each row.
- Minimisation is solved as `maximise -C`; the reported value is converted
  back to `C`.
- Big-M is symbolic: coefficients are `a + bM` with lexicographic ordering,
  never a large-number substitution.
- Very large symbolic derivative trees are rejected with a request for a lower
  degree; this keeps the `series` WASM allocation bounded.
- Graph weights are parsed as exact rationals in `graphnet`; missing matrix
  cells mean no edge.

## Known limits

- Simplex: no multiple-optimum detection, unrestricted variables, integer
  programming, or sensitivity analysis.
- Graphs: critical path analysis, route inspection, max flow and the visual
  graph editor are not implemented yet. The current release covers Dijkstra,
  Floyd–Warshall, Kruskal and Prim over an adjacency matrix.
- Boolean: the cover after finding prime implicants is greedy, not an exact
  Petrick cover. There is no K-map or don't-care input yet.
- Floating point: bit-field arithmetic, rounding modes and ULP analysis are
  not implemented yet. Irrational numeric roots are approximated.
- Matrix: arithmetic, eigenvalues/eigenvectors, LU/QR and least squares are
  not implemented yet.
- Complex: expression input, complex functions and loci are not implemented
  yet.
- Series: degree is capped at 12, the centre must be rational, and there is no
  remainder bound, interval of convergence or trigonometric simplification.
- Arabic is frozen; the `data-ar` translations remain dormant.
- No practice/quiz mode (explicitly out of scope).
- No bundled analytics. Calculations stay in the browser; the host may keep
  basic request logs.

## Verification

CI runs these on every push and pull request; a failure blocks the Pages
deploy:

```sh
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets -- -D warnings
cargo test --manifest-path rust/Cargo.toml --workspace
npm run check
npm test
npm run build
npm run size
npm run test:e2e
```

- Rust: 72 tests covering parsing, exact arithmetic, overflow errors,
  maximisation, minimisation, Big-M, equality constraints, negative RHS,
  infeasibility, unboundedness, RREF, determinant, inverse, nullspace,
  linear systems, complex arithmetic, polar form, powers and roots, graph
  shortest paths, spanning trees, weight overflow, Taylor/Maclaurin
  expansion, general-term detection, truth tables, Boolean minimisation,
  base conversion, normalisation and IEEE 754.
- Vitest: 16 unit tests for the LaTeX-to-canonical parser and LaTeX helpers.
- Playwright: all routes return `200` without console errors, every generated
  WASM module is served, the default simplex problem solves, a Maclaurin
  expansion and its general term run, and the home page does not overflow on
  mobile.
- The LaTeX preview renders the exported document body itself, so the
  preview, the source dropdown and the copied/downloaded file cannot drift.
